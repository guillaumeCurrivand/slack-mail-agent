# Select repositories explicitly without reorganizing ClickUp

The User requires frontend and backend maintenance to retain one Slack channel, Folder and List, and allows a ticket to affect both repositories. Folder membership cannot choose a repository, and AI inference would silently authorize paid work in an unintended checkout. Store an explicit shared ticket repository selection, confirmed through private owner-bound controls, then atomically admit a maintenance batch with identical frozen requirements. Keep repository execution and commits independent, but checkpoint the shared `to build` effect only after every selected correction has pushed. Retain successful sibling results when retrying one correction; do not invent a cross-repository rollback. Existing unassigned work is held for reconciliation when a Folder becomes shared, rather than retroactively assigning it. The [feature contract](../development.md#shared-tickets-across-repositories) owns the current workflow and limits.

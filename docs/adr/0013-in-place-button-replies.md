# Keep button replies on the originating Card

The User requested consistent in-place Slack interaction on 13/10/2026. Extend recorded navigation to workflow replies and carry signed source timestamps through durable dispatch, so both `Messenger.send` and module-owned `Navigation.show` reuse an owner/conversation-verified target. This avoids separate module implementations and preserves the delivery-recovery rules of [saved navigation](0008-saved-navigation-content.md). Prepared Development forms retain the source timestamp for queued validation after the modal closes.

The trade-off is that navigation replaces the displayed approval or result; authorization and history continue to live in independent module records and remain reachable through existing controls. A timestamp alone never grants edit permission. Unrecorded legacy Cards and public notices cannot be safely adopted as a User's screen, so their first interaction opens personal controls or recovery guidance. This revises the separate result-Card presentation in [Documentation's decision](0004-authoritative-documentation-inventory.md), without changing its saved confirmation or spending boundaries. The [product contract](../product-spec.md#in-place-button-interactions) owns current behavior and exceptions.
